# RAG_new_exps — 检索投毒治理的博弈模型验证实验

本仓库是论文《When Retrieval Becomes Strategic》修改阶段配套的实验代码与结果仓库。
审稿意见指出：论文中博弈模型的结论缺少直接的实验支撑。本仓库按照"定理先行"的原则，
设计了一组完全不依赖大模型接口、只在普通电脑 CPU 上运行的检索实验，逐条验证模型
的每一个可检验结论。

全部实验只做三件事：把注入文档放进检索索引、按查询取回前十条、数其中有多少条是
注入的文档。检索器使用与原实验完全相同的配置：

- 向量模型：BAAI/bge-small-en-v1.5（均值池化，向量归一化）
- 切块方式：每篇文档切成约 512 字符的块，相邻块重叠 64 字符
- 检索方式：FAISS 精确 L2 距离，取前 10 条（记号 k=10）

## 三、公共工具库 src/replay_lib.py

所有实验共用以下能力，确保任何一个实验的"注入、检索、计数"方式完全一致：

1. 文本切块与缓存。把每篇文档切成约 512 字符的块。同一个文本只切一次，
   切好的块在进程内缓存；文本向量也做了跨进程的磁盘缓存
   （results/cache/vec_cache.pkl），同一句话全仓库只计算一次向量，
   后续任何实验直接复用。这是整套实验能在普通 CPU 上跑完的关键。
2. 检索索引与曝光计数。把"真实语料的块 + 注入文档的块"放进同一个
   FAISS 索引，对每条查询取回前 10 条，数其中属于注入文档的条数。
   一个配置的曝光值，就是 44 条查询上"前 10 条里注入文档占比"的平均。
3. 博弈方程求解。提供两个函数：
   一是根据检索阻力与参与商家数、过滤强度，解出模型预言的均衡曝光；
   二是根据容忍曝光线反推理论要求的最低过滤强度。
   这两个函数是实验一和实验三"理论预言"列的唯一来源。

## 四、如何运行

单机、串行、无需任何接口密钥：

```
# 一次性安装依赖（python 版本 3.11，向量模型会自动下载到本地缓存）
python3 -m pip install -r requirements.txt

# 一键跑完全部实验（推荐，严格串行，各阶段进度写入 results/status.txt）
bash scripts/run_all.sh

# 或者只跑某一个实验（示例：实验一）
python3 src/e1_filtering.py            # 默认相机域
python3 src/e0_calibration.py ev       # 校准实验换电动车域

# 实时查看进度
tail -f results/status.txt

# 让新结果自动推送到 GitHub（可选，参数为间隔秒数）
bash scripts/sync_loop.sh 180
```

注意事项：
- 全部实验串行执行时约需 1.5 到 2 小时（首次运行需要为所有语料计算向量，
  之后因为磁盘缓存的存在，重跑任何实验都只需几分钟）。
- 请不要同时运行两个实验脚本。向量计算吃内存，两个进程并行会触发
  系统的内存保护把进程杀掉。
- 每个实验的完整控制台输出都落在 logs/ 目录下对应名字的文件里。

## 五、校准实验：量出真实内容的检索阻力

### 目的

模型的核心假设是"曝光形成定律"：注入内容能抢到的曝光，取决于注入占比与
真实内容阻力之间的竞争，形式为 曝光 = 注入占比 除以（注入占比 + 检索阻力）。
这条定律里唯一的未知数就是检索阻力。校准实验把它量出来，供后面所有实验
做理论对照时使用。同时它本身也验证了定律的形状是否成立。

### 实验步骤

1. 读入相机域的 1000 条真实评测，切成块（相机域约 2400 块），做成检索索引。
2. 把激进注入池的 176 条文档分成两半，模拟两个 Injection 提供者，
   各持 88 条。每次实验从中抽取一部分注入。
3. 枚举注入组合：两家各注入 0、10、20、40、80 条的全部组合，再补上
   5 个低注入组合（两家各 2 条、各 5 条、各 10 条、一家 5 条另一家 0 条、
   反之亦然），共约 30 种组合。
4. 每种组合用 3 个随机种子（101、202、303）各做一遍：随机决定每家具体
   注入哪几条文档，把选中文档的块加入索引，然后用相机域 44 条真实查询
   逐条检索，按公共工具库的方式数出曝光值。
5. 把全部数据点（曝光 与 注入占比的对应关系）用"曝光 = X 除以（X 加 阻力）"
   的曲线做最小二乘拟合，得到检索阻力的估计值与拟合优度。
6. 换电动车域重复第 1 到第 5 步（运行命令 python3 src/e0_calibration.py ev）。
   换球鞋域同理（python3 src/e0_calibration.py shoes）。球鞋域的注入池
   共 184 条，每家 92 条，查询池 39 条，语料 918 篇，其余流程完全相同。

### 输出文件与字段

- results/e0/e0_grid_camera.csv、results/e0/e0_grid_ev.csv、
  results/e0/e0_grid_shoes.csv：逐点原始数据
  - seed：随机种子（101、202、303）
  - n_A、n_B：两家各注入的文档条数
  - X：注入占比，即两家合计注入条数除以注入池总量 176
  - exposure：实测曝光，44 条查询上"前 10 条里注入占比"的平均值
  - n_inj_chunks：注入文档实际切成的块数（记录用）
- results/e0/e0_fit_camera.json、results/e0/e0_fit_ev.json、
  results/e0/e0_fit_shoes.json：拟合结论
  - rho_hat：拟合出的检索阻力（相机域 0.334，电动车域 0.919，球鞋域见
    results/e0/e0_fit_shoes.json，说明不同域的真实内容抵抗力差别很大，
    它是域级属性）
  - r2：拟合优度（两域都超过 0.96，定律形状成立）
  - mae：平均绝对误差；rmse：均方根误差；n_points：参与拟合的数据点数（87）

## 六、实验一：过滤强度与策略性注入（对应模型定理：机械过滤与均衡可实现）

### 目的

回答三个问题。第一，平台按比例删除注入文档时，曝光是否按"注入占比打折扣"
的方式衰减（机械过滤）。第二，注入方如果知道过滤强度、按博弈模型的最优
反应决定注入量，最终曝光是否真的落在理论均衡曲线上（均衡可实现性）。
第三，模型给出的"最低过滤强度"是否真能把曝光压到容忍线以下（闭锁点）。

### 实验步骤

1. 读入相机域真实语料与查询，检索阻力取校准实验的相机域结果 0.334，
   容忍曝光线取 0.3（即每次回答的 10 条证据里最多 3 条被污染）。
2. 固定注入臂（笨办法）：两家各固定注入 40 条（合计 80 条）不变。
   对过滤强度 0、0.2、0.4、0.6、0.8、0.95 逐档执行：随机把已注入的文档
   删掉 r 比例，用剩余部分重建索引，44 条查询重新检索并计数曝光。
   理论预言列直接代入公式 曝光 = (1 减 r) 乘 X 除以（(1 减 r) 乘 X 加 0.334），
   其中 X 是固定的 0.455（80 除以 176）。
3. 策略注入臂（聪明办法）：先解博弈方程，得到在当前过滤强度下注入方的
   均衡曝光 q*(η) 与每家应注入的条数 x*；两家各按 x* 注入，然后同样随机
   删掉 r 比例（模拟平台过滤照常执行），用剩余部分重建索引、重新计数。
   理论预言列就是均衡曝光 q*(η)。这一臂测的是"过滤后"的曝光，与理论
   的可比性是设计要点。
4. 两个臂都在同一组随机种子（101、202、303）下重做三遍取平均。
5. 计算闭锁点：按公式反推理论要求的最低过滤强度（约 0.80），核对实测
   曝光在该点是否压到 0.3 以下。
6. 同时把每个查询的逐条结果存下来，供稳定性检验使用。

### 输出文件与字段

- results/e1/e1_camera.csv：逐配置结果，一行是一个种子、一个臂、一个过滤档位
  - seed：随机种子
  - arm：fixed（固定注入臂）或 adaptive（策略注入臂）
  - r：过滤强度，即随机删除注入文档的比例
  - n_planned：过滤前计划注入的文档条数（策略臂即理论最优量）
  - n_injected_docs：过滤后实际留在索引里的文档条数
  - q_measured：重新检索计数得到的实测曝光
  - q_pred：理论预言的曝光（固定臂代入打折公式；策略臂取均衡曝光）
  - abs_err：实测与预言的偏差绝对值
- results/e1/e1_camera_perquery.csv：逐查询细账，供稳定性检验复用
  - q_idx：第几个查询；n_inj：该查询前 10 条里注入文档的条数
  - q_run：该查询的注入占比；hit：是否至少混入 1 条（0 或 1）
  - rr_weighted：按排名加权的污染得分（排位越靠前权重越高）
- results/e1/e1_camera.png：两臂的"过滤强度 对 曝光"曲线图，
  实线圆点为实测，虚线为理论预言

### 主要结论

固定臂 6 个过滤档位的偏差在 0.004 到 0.034 之间，证明机械过滤按乘性方式
生效；策略臂偏差在 0.011 到 0.066 之间，证明理论均衡在真实检索系统里
可以被走到；过滤强度 0.8（理论闭锁点）处实测曝光 0.25，低于容忍线 0.3；
完全不过滤时策略注入能把曝光做到 0.81，是容忍线的 2.7 倍。

## 七、实验二：真实内容体量的防御作用（对应模型结论：检索阻力杠杆）

### 目的

模型的治理建议之一是"扩充真实内容可以稀释注入"。实验二回答：真实语料
变大变小时，曝光如何变化；由实测反推的检索阻力是否随语料规模等比变化。

### 实验步骤

1. 读入相机域语料，对语料规模设三个档位：保留全部 1000 篇、随机保留
   500 篇、随机保留 250 篇（保留哪 250 篇由随机种子决定，是随机抽样
   而不是取前缀，避免题材偏窄的干扰）。
2. 设计两个对照臂。
   固定注入臂：无论语料多大，永远注入同样的 80 条文档。它回答
   "语料缩小后，同样多的注入会更严重吗"。
   等比注入臂：注入量随语料等比缩放（语料 250 篇时注入 20 条），
   使注入在索引里的占比保持不变。它回答"占比相同时，语料规模本身
   有没有独立的防御作用"。
3. 每个臂、每个档位、每个种子（101、202、303）都重新建索引、
   重新检索、重新计数曝光，并用实测曝光反推隐含检索阻力
   （公式：阻力 = 占比 乘（1 减 曝光）除以 曝光）。
4. 计算隐含阻力除以语料比例。若阻力真随语料等比变化，这一列应当
   是常数。

### 输出文件与字段

- results/e2/e2_camera.csv：逐配置结果
  - seed：随机种子；arm：abs80（固定注入臂）或 scaled（等比注入臂）
  - frac：语料保留比例（0.25、0.5、1.0）
  - n_corpus_docs：该档位保留的真实文档篇数
  - corpus_chunks、inj_chunks：真实语料与注入文档各自切成的块数
  - X：注入在索引中的真实占比（注入块数 除以 总块数）
  - q_measured：实测曝光
  - rho_implied：由实测曝光反推的隐含检索阻力
  - rho_per_frac：隐含阻力除以语料比例（等比检验列）
- results/e2/e2_camera_summary.json：两臂各自按档位的均值汇总
  - rho_implied_mean：各档位隐含阻力的三种子平均
  - ratio_to_full：各档位相对全量语料的倍数
  - rho_per_frac_mean：等比检验列的均值

### 主要结论

固定注入臂下，语料缩到四分之一时曝光从约 0.60 升到约 0.78，扩充真实
内容确实稀释污染，防御方向成立。隐含阻力在语料缩到四分之一时只从
0.037 变到 0.053，远不是等比变化，说明阻力由"与查询最相关的那部分
真实内容"决定，而不是由语料总量决定，支持论文把检索阻力当作域级
常数、按域拟合一次的做法。等比注入臂显示：占比相同时，注入文档的
绝对条数决定每条查询能碰到的定向广告数量，这提示模型中的注入占比
应理解为"与查询相关的注入内容量"。

## 八、实验三：商家数量与竞争结构（对应模型比较静态结论）

### 目的

验证三条关于"作弊市场结构"的预言。第一，参与注入的商家越多，单个
商家注入越少（搭便车），但总曝光反而更高。第二，作弊越划算
（收益代价比参数调高），均衡曝光越高。第三，两家成本不同时，
低成本商家占走大部分曝光。

### 实验步骤

1. 读入相机域语料、查询与 176 条激进注入池。检索阻力用校准值 0.334。
2. 造商家：把 176 条注入池平均分成 N 份，每份是一个独立商家，
   互不重叠。N 取 1、2、4、8。
3. 笨商家对照臂：每家固定注入 5、10 或 20 条（三个剂量乘四个家数，
   共 12 种组合）。理论预言列按总注入占比代入曝光定律。这个臂
   展示"不进行策略调整时"曝光随家数的机械增长。
4. 聪明商家均衡臂：先解博弈方程得到 N 家竞争时的均衡曝光 q*(N)，
   再反推每家应注入的条数 x*(N)，按这个数量注入并测量曝光。
   收益代价比参数需要事先定死一次：把它校准到"N 等于 2 时均衡
   曝光恰为 0.5"（数值约 0.148）。之所以不取更大的值，是因为每家
   手里的注入池有限，理论要求数量超出池子就无法执行；定死之后
   所有家数档位通用，不再逐点调整。
   高收益对照：另跑一组收益代价比等于 1 的均衡注入（家数 1 与 2
   可行），展示参数调大后均衡曝光抬升。
5. 收益比扫描：固定 2 家，把收益代价比设为 0.5、1、2 三档，
   每档按理论最优量注入。收益比为 2 时理论要求每家 122 条，超出
   池子上限 88 条，实际只能注入 88 条，结果表里用 capped 标记
   这种撞上限的档位。
6. 成本不对称：设两家单位成本之比为 0.5 比 2（便宜家每塞一条的
   代价只有贵家的四分之一）。解两组方程得到各自理论注入量
   （便宜家约 47 条、贵家约 16 条），分别注入并把两家的文档
   分开标记。曝光份额的计算：44 条查询各自前 10 条证据里凡是
   命中的注入块，按所属商家累计，除以全部命中数。
7. 全部配置在三个种子下重做取平均。

### 输出文件与字段

- results/e3/e3_camera.csv：逐配置结果
  - seed：随机种子
  - arm：配置类型，取值 equal_m（笨商家固定剂量）、
    equilibrium_w*（聪明商家，校准收益比）、equilibrium_w1（收益比 1）、
    omega_0.5 / omega_1.0 / omega_2.0（收益比扫描）、
    asymmetric_c(0.5,2)（成本不对称）
  - N：参与商家数；m：每家注入条数
  - X_docs：全部商家合计注入的文档条数；X：对应的注入占比
  - q_measured：实测曝光；q_pred：理论预言的均衡曝光
  - x_star_docs：理论说每家该注入的条数
  - capped：是否撞上池子上限（1 是，0 否）
  - share_lowcost、share_highcost：便宜家与贵家的曝光份额
    （只有成本不对称行有值）
  - x_pred_low_docs、x_pred_high_docs：理论预测两家各注入几条

### 主要结论

均衡臂下每家注入量随家数从 32 条降到 19 条（搭便车出现），总曝光
从 0.375 升到 0.782，四个档位的实测与理论偏差都不超过 0.08；
收益比扫描三档实测 0.72、0.81、0.82 对理论 0.67、0.74、0.81；
成本不对称时便宜家占曝光份额 77%，贵家 23%，方向与理论一致。

## 九、实验四：检测偏差（对应模型结论：选择效应 kappa 大于 1）

### 目的

模型的治理分析依赖一个关键前提：依靠"与已有内容过于相似"来检测
注入文档时，被检测器放行的注入文档恰恰是那些能被检索到的激进文档。
也就是说，名义过滤强度会打折扣，实际防线弱于名义值。实验四量出
这个折扣系数。

### 实验步骤

1. 对三个域分别执行：读入真实语料、简单注入池（每域 100 条普通
   模板文档）与激进注入池（每域约 180 条定向优化文档）。
2. 可检索性标注：把全部注入文档的块与真实语料的块放进同一个
   候选池，对每个域的全部真实查询逐条计算"如果这篇注入文档在场，
   它能否进入前 10"。一篇文档的可检索性，就是它出现在前 10 的
   查询比例。
3. 检测器打分：给每篇注入文档计算两个分数。
   最大相似度：它与全部真实内容块的最大余弦相似度。
   密度分数：它与最相似的 5 篇真实内容块的平均相似度。
   分数越高代表越容易被"与已有内容雷同"的检测器抓住。
4. 模拟过滤：对每个名义过滤强度 r（取 0.2、0.3、0.5、0.7、0.9），
   把检测分数最高的 r 比例注入文档删掉，留下的部分模拟"漏网之鱼"。
5. 计算折扣系数：幸存文档的可检索性总和除以全体文档的可检索性
   总和，再除以 (1 减 r)。若检测与可检索性无关，这个系数应约为 1；
   若过滤放走的恰是高可检索性文档，系数显著大于 1。
6. 同时分别统计"可检索文档的幸存率"与"不可检索文档的幸存率"，
   两者之差是选择偏差的直接证据。

### 输出文件与字段

- results/r2/kappa_table.csv：一行是一个域、一类文档、一种检测器、
  一个过滤档位
  - domain：相机、电动车或球鞋
  - doc_type：simple（简单模板注入）或 cpa（定向优化注入）
  - detector：max_sim（最大相似度）或 density_top5（五篇平均相似度）
  - nominal_recall：名义过滤强度 r
  - kappa：折扣系数，大于 1 说明过滤放走的恰是危险文档
  - eta_eff：幸存内容的可检索性总和占全体的比例
  - p_survive_retrievable：本身可被检索到的注入文档的幸存率
  - p_survive_unretrievable：本身检索不到的注入文档的幸存率
  - retrievability_any：该类文档至少在一条查询里进前 10 的比例
  - retrievability_mean：该类文档的平均可检索性

### 主要结论

激进注入文档约四分之三的查询可以进前 10（相机域 0.739，电动车域
0.729），简单模板注入只有 0.03 甚至 0。过滤按名义强度执行后，幸存
内容的可检索性比例高于名义保留比例，折扣系数最高约 1.43。这直接
支持模型"名义过滤强度需要按选择效应打折后才能达到治理目标"的论断。

## 十、指标稳定性检验

### 目的

排除"实验结论来自抽签运气"的质疑。做法是把逐查询指标的总方差
分解为"实验条件之间"与"同一条件内不同种子之间"两部分。若结果
由条件驱动，条件之间的一致度应高、种子之间应接近零。

### 实验步骤

1. 读入实验一输出的逐查询细账（results/e1/e1_camera_perquery.csv）。
2. 对三个逐查询指标（注入占比、是否命中、排名加权得分）分别计算
   条件间一致度与种子间一致度。
3. 输出每个指标的均值与标准差作参考。

### 输出文件与字段

- results/r1p/metric_stability_camera.csv
  - metric：指标名（q_run 注入占比、hit 是否命中、rr_weighted 排名加权得分）
  - icc_condition：条件之间的一致度（越高说明不同过滤档位确实产生
    系统性差异）
  - icc_seed：种子之间的一致度（接近零说明同一条件内重做只是噪声）
  - mean、std：该指标在全部配置上的均值与标准差

### 主要结论

条件之间一致度 0.46 到 0.61，种子之间接近 0（约 0.0001）。
实验差异由实验条件驱动，不是抽样噪声。

## 十一、日志解析与既有实验数据的再分析

这一组脚本不产生新实验，而是把论文原实验留下的日志与汇总表格
变成可分析的数据，回答两个审稿人关心的链条问题。

### src/parse_logs.py：解析重跑日志

输入是 logs/ 目录下 5 个种子日志（种子 11、22、33、44、55），每个
日志记录了相机域、注入比例 0.1、取前 10 设定下，注入量从 0 到 200
逐档的完整过程：每次查询的检索列表（每条包含来源文件与行号、
相似度分数、排名）、注入构成、以及裁判对回答是否被带偏的判定。

输出：
- results/parsed/seed_11.json 等 5 个文件：每个种子的逐查询记录，
  包括查询文本、检索到的条目（来源、行号、分数、排名）、注入构成、
  裁判判定与理由。
- results/parsed/parse_summary.csv：按种子与注入量汇总的曝光值与
  攻击成功率，用于与历史结果对账。
- results/parsed/queries_per_seed.json：每个注入档位里实际出现过的
  查询数（查询池 44 条，每档位抽样约 50 次，会有重复）。

### src/r4_anchor.py：跨生成器锚点

背景：原实验的曝光数据由旧生成器产生，重跑日志由新生成器产生，
检索端逐字节一致而攻击成功率不同。此实验把"新测得的曝光量"与
"新旧两套攻击成功率"放在一起，检验"曝光量决定攻击成功率"这条
链条是否跨生成器成立。

输出：
- results/r4/anchor_summary.csv：按注入档位逐行
  - adv_count：注入文档条数（0 到 200，步长 10）
  - exposure_new：重跑日志里测得的曝光
  - asr_new：新生成器下裁判判定的攻击成功率
  - delta_asr_new：相对零注入档位的成功率提升
  - asr_hist、delta_asr_hist：历史结果中的同款数字
- results/r4/per_query_camera_ratio0.1.csv：逐查询细账
- results/r4/r4_anchor_overlay.png：新旧两条"注入量 对 成功率提升"
  曲线的叠加图

主要结论：曝光量与两代生成器的成功率提升都高度单调相关
（斯皮尔曼相关 0.939），曝光作为"治理目标量"不依赖于具体生成器。

### src/r1_metrics.py：哪种污染指标最能预测回答被带偏

背景：治理需要一个便于测量的代理指标。此实验把五个候选指标
（注入占比、是否命中、命中条数、排名加权得分、分数加权得分）
在既有条件上比较它们预测"裁判判定被带偏"的能力。

输出：
- results/r1/single_condition_camera_ratio0.1.csv：每个指标一行
  - subset：参与计算的查询集合（all 为全部）
  - metric：指标名
  - auc_pooled：把全部查询合在一起时，该指标区分"被带偏与未被
    带偏"的曲线下面积（0.5 等于瞎猜，1 为完美）
  - auc_seed_mean、auc_seed_std：按种子重抽样的均值与标准差
  - ci95_lo、ci95_hi：95% 置信区间
  - spearman_mean：该指标与判定的秩相关

主要结论：考虑排名位置的指标最好（约 0.77 到 0.79），"是否命中"
这种粗指标明显更差（约 0.63）。治理目标应选排名加权的曝光量，
而不是简单的命中与否。

## 十三、结果文件与日志的自动同步

scripts/sync_loop.sh 以指定间隔（默认 180 秒）循环执行：把 results/

```
bash scripts/sync_loop.sh 180        # 前台运行
setsid nohup bash scripts/sync_loop.sh 180 > logs/sync_loop.out 2>&1 &   # 后台运行
```

推送使用仓库配置里的凭据；如需更换目标仓库或凭据，修改
git remote 或本机的凭据配置即可，脚本本身不含密钥。

## 十四、复现清单（从零开始）

1. 准备 python 3.11 与 requirements.txt 中的依赖。
2. 把数据目录（dataA、dataB、logs、new_result、expb_result、
   expa_result.csv、queryA.py、queryB.py）放到仓库上一级目录。
3. 运行 bash scripts/run_all.sh，等待 status.txt 出现 run_all DONE。
4. 打开 results/summary/SUMMARY.md 查看全部关键数字；
   各实验的原始表在 results/ 对应子目录。
5. 首次运行会自动下载向量模型（约 130 MB）并为全部语料计算向量，
   约 1.5 到 2 小时；此后重跑任何单个实验都在几分钟内完成。

## 十五、已知限制

- 所有实验都基于向量检索的确定性重放，不包含大模型接口调用；
  攻击成功率链条通过日志解析与锚点实验间接连接。
- 注入池规模有限（每域约 180 条），实验三中理论最优注入量超出
  池子的档位会触发上限截断，结果表以 capped 列标明，解释时
  需按"上限约束下的饱和"处理。
- 检索阻力按域拟合（相机 0.334、电动车 0.919、球鞋域见
  results/e0/e0_fit_shoes.json），跨域不可混用；
  实验二进一步说明它对语料规模也不敏感，宜视为域级常数。
